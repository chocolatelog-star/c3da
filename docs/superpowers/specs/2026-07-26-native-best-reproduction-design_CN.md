# 当前代码原生最佳流程复现设计

## 1. 目标

将已经从头精确复现的 `rest16 -> laptop14` 历史最佳流程迁移为当前代码的正式能力。正式入口只能执行当前分支代码，不再依赖 `.worktrees` 中的 `9e78904`、`8c7f6b4` 等历史工作树，也不得读取其他实验目录中的模型、伪标签、增强数据或最终训练集。

验收基准如下：

| 产物或指标 | 黄金基准 |
|---|---:|
| 基础高精度伪标签 | 421 条 |
| 双通道增强 | 150 条 |
| 完整双三元组伪标签 | 494 条 |
| 最终训练集 | 1499 条 |
| raw F1（原始 F1） | 48.92703862660945 |
| fixed F1（修正 F1） | 50.21459227467810 |

提取器、生成器、基础伪标签、补全伪标签、最终训练集、最终模型和预测文件还必须通过保存的 SHA256 文件哈希校验。增强阶段以进入最终训练集的 150 条 `text + label` 为黄金内容校验对象，避免被后来覆盖的同名增强文件误导。

## 2. 版本治理

所有代码和实验改动必须从当前 `master` 创建独立分支：

- 功能开发：`feature/<topic>-vN`
- 实验候选：`experiment/<topic>-vN`
- 缺陷修复：`fix/<topic>-vN`
- 历史审计：`historical/<commit-or-topic>`

`master` 永远指向当前已经完整验证的最佳版本。候选分支只有同时满足以下条件才允许合并：

1. 单元测试、集成测试和试运行全部通过。
2. 模型行为变化已完成独立输出目录的 GPU 全流程实验。
3. 代码、环境、命令、输入、输出和指标均已归档。
4. 达到该分支事先声明的验收指标。
5. 中文总览和单次运行记录已经更新。
6. 分支与提交已成功推送到 GitHub。

失败或未超过当前最佳的实验不得合并到 `master`。失败实验保留分支、命令、指标和清单；模型与大文件仅在用户明确许可后删除。

## 3. 总体架构

### 3.1 当前代码正式入口

新增当前代码原生入口：

```text
run_best_reproducible_pipeline.ps1
```

入口只调用当前仓库根目录中的 `t5_aste_pipeline.py`、`t5_absa_train.py` 等模块。正式入口中禁止出现：

- `.worktrees` 路径；
- 历史提交目录；
- `--reuse_upstream_run_dir`；
- 指向其他 `runs` 子树的模型或数据输入；
- 缺少当前文件时回退读取旧文件的逻辑。

现有 `run_historical_best_two_stage.ps1` 保留为历史审计入口，在文档中明确标记为非正式训练入口。

### 3.2 版本化实验配方

新增机器可读配方：

```text
configs/recipes/rest16_to_laptop14_best_v1.json
```

配方固定数据集、模型、轮数、检查点选择、筛选规则、权重、解码参数、随机模式、GPU 参数、阶段顺序、预期行数和黄金哈希。任何影响行为的参数变化都必须新建配方版本，禁止修改已用于正式结果的配方。

### 3.3 Python 编排与 PowerShell 包装

PowerShell 入口负责 Windows 环境启动和用户可见的一行命令；核心编排、血缘校验和命令归档由 Python 模块负责，避免在 PowerShell 中重复实现复杂结构化逻辑。

新增：

```text
reproducibility.py
run_reproducible_pipeline.py
```

`reproducibility.py` 负责清单、哈希、环境、命令和血缘校验；`run_reproducible_pipeline.py` 读取配方并依次调度现有训练命令。

## 4. 运行目录与隔离

每次正式运行必须使用独立 `run_id`，目录结构为：

```text
runs/reproducible/<recipe_id>/<run_id>/
  run_command.cmd
  commands.jsonl
  RUN_RECORD_CN.md
  manifest.json
  environment.json
  stage_status.json
  logs/
  data/
  models/
  metrics/
```

所有阶段输入必须位于本次运行目录，只允许以下两类外部只读输入：

1. 配方声明的原始数据集文件；
2. 配方声明的模型目录，包括 T5-base 基础模型和 NLI 模型。

每个阶段产物都记录：

```text
run_id
recipe_id
git_commit
git_branch
producer_stage
input_hashes
output_hash
created_at
command_id
```

下游读取产物前验证路径、运行编号、配方版本、生产阶段和输入输出哈希。任一项不匹配立即失败，不允许警告后继续。

## 5. 新运行与断点恢复

入口默认采用以下规则：

- 目标目录不存在：创建新运行并写入不可变初始清单。
- 目标目录存在且清单完全匹配：从本次运行最近检查点恢复，增加 `resume_count`。
- 目标目录存在但缺少清单：拒绝运行。
- Git 提交、配方、数据哈希、基础模型哈希或关键环境与清单不一致：拒绝恢复。
- 已完成阶段只有在产物存在且哈希匹配时才能跳过。
- 检查点只能位于本次运行的模型目录。

这样保留“断电后执行同一条命令继续”的体验，同时阻止把其他实验的中间文件误当作本次检查点。

## 6. 命令与环境归档

### 6.1 命令文件

每次运行自动保存：

- `run_command.cmd`：用户从 CMD 执行的完整单行命令；
- `commands.jsonl`：每个阶段的精确参数数组、工作目录、开始和结束时间、退出码、日志路径；
- `RUN_RECORD_CN.md`：中文可读的总命令、展开命令、参数、产物、指标和结论。

命令由编排器在执行前写入，执行后补充退出码。失败命令也必须保留，不能只记录成功命令。

### 6.2 环境文件

`environment.json` 至少记录：

- Windows、Python 和 Conda 环境；
- PyTorch、Transformers、Accelerate、CUDA 和 cuDNN 版本；
- NVIDIA 驱动、GPU 型号和显存；
- `pip freeze` 的排序后哈希及完整依赖快照路径；
- 基础模型关键文件哈希；
- 与随机性相关的环境变量和训练器参数。

工作树有未提交改动时，正式模式拒绝运行；诊断模式可以运行，但必须将 diff 保存进运行目录并明确标记为非正式结果。

## 7. 黄金基准与提前失败

`rest16_to_laptop14_best_v1` 在每个阶段完成后立即校验：

1. 提取器权重哈希；
2. 421 条基础高精度伪标签及哈希；
3. 生成器权重哈希；
4. 150 条增强的有效训练内容；
5. 494 条补全伪标签及哈希；
6. 1499 条最终训练集及哈希；
7. 最终模型权重哈希；
8. 328 条目标测试预测及哈希；
9. raw/fixed 指标和 TP、FP、FN。

若某阶段与黄金基准不符，默认停止后续昂贵阶段，并在 `RUN_RECORD_CN.md` 中写明首个偏差点。新实验配方可以没有黄金模型哈希，但必须声明自己的行数、质量门槛和最终验收指标。

## 8. 文档组织

根目录 `实验记录与模型索引_CN.md` 继续作为当前状态索引，不在末尾堆积完整命令。每次运行在自己的 `RUN_RECORD_CN.md` 中保存完整命令，根目录索引记录：

- recipe 版本；
- 分支和提交；
- run_id 与运行目录；
- raw/fixed 指标；
- 是否通过来源和黄金校验；
- `RUN_RECORD_CN.md` 与 `manifest.json` 路径；
- 保留或清理状态。

本次成功结果应将“历史组合最佳”升级为“当前代码迁移前的完整可复现黄金基准”，并把下一阶段目标改为完成当前代码原生迁移。

## 9. 项目对话规则

更新 `docs/skills/c3da-experiment-workflow/SKILL.md`，并在项目根目录新增 `AGENTS.md`。`AGENTS.md` 要求未来进入本项目的代理先读取该 Skill，执行以下硬性规则：

- 修改前创建新分支；
- 不在 `master` 直接开发；
- 禁止跨运行复用或混合产物；
- 每次训练自动保存完整命令；
- 必须记录 Git、环境、数据、模型和产物哈希；
- 模型变更必须用 GPU 完整验证；
- 未完成全流程验证不得宣称可复现；
- 未达到验收标准不得合并 `master`；
- 删除文件前必须获得用户许可；
- 修改和实验结束后整体更新中文文档。

可以由程序机械验证的要求必须同时在代码中强制执行，不能只依赖 Skill 文本提醒。

## 10. 测试与验收

### 10.1 自动化测试

先编写失败测试，再实现功能。测试至少覆盖：

- 正式入口不包含历史工作树或复用参数；
- 产物路径逃出当前运行目录时拒绝；
- 运行编号或配方不匹配时拒绝；
- 已有目录无清单时拒绝；
- 清单匹配时正确恢复；
- 已完成阶段哈希损坏时拒绝跳过；
- 每条阶段命令在执行前被记录；
- 失败命令保留退出码和日志；
- `RUN_RECORD_CN.md` 包含用户总命令和全部训练命令；
- 当前代码的试运行展开参数与黄金配方一致；
- 正式入口和配方中没有其他实验目录的绝对路径。

### 10.2 GPU 全流程验收

自动化测试通过后，在 RTX 3070 8GB 上使用新运行目录从头训练。只有关键哈希与 `48.93/50.21` 全部复现，才将该分支合并进 `master`，并创建带注释标签：

```text
best-rest16-laptop14-v1
```

若未通过，不修改 `master`，保留分支、日志、命令、清单和首个偏差点，继续在新的修复分支处理。

## 11. 实施边界

本次只迁移已验证最佳流程及其可复现基础设施，不同时开发新的模型损失、筛选策略或指标优化。历史工作树和旧运行目录不删除；它们只从正式运行依赖降级为审计证据。
