# C3DA 双通道增强第二版实施计划

> **执行规则：** 按项目 Skill（技能）要求，由当前智能体直接逐项实现和自查，不启动多个智能体。每个任务先写失败测试，再做最小实现并单独提交；用户明确要求前不启动正式训练。

**目标：** 修复增强通道“生成失败但被重新贴标保留”的核心错误，建立与生成意图一致的双通道过滤、分层配额和训练权重，并在三个代表跨域方向验证收益。

**架构：** 第一阶段只修复数据增强闭环，不修改最终提取器结构、领域对抗和情感对比参数。过滤器先执行通道编辑契约硬约束，再使用 NLI（自然语言推断）和抽取器作为软支持；选择器按通道、情感和结构分层。只有数据增强稳定有效后，才实施共享生成器的编辑任务对齐和分层训练权重。

**技术栈：** Python 3.10、PyTorch（PyTorch框架）、Transformers（转换器库）、T5-base（T5基础模型）、DeBERTa NLI（DeBERTa自然语言推断模型）、RTX 3070 8GB、`unittest`（单元测试框架）、PowerShell（脚本环境）。

## 3. 全局正确性不变量

选中增强必须同时满足：

1. 生成文本和最终标签不含 `[OPI]`、`[ASP]`、`<opinion>` 等控制占位符。
2. 方面通道的新方面出现在文本和最终标签中，旧方面消失，原观点和情感保持。
3. 观点改写的新观点出现在文本和最终标签中，方面和目标情感保持。
4. 情感转换的新观点和目标情感同时实现，旧观点消失。
5. 未编辑三元组完整保留；不能因为编辑失败而只训练句中剩余的其他三元组。
6. 抽取器只能提供支持分，不能把失败编辑重新贴成无关标签后保留。
7. 每条拒绝记录保存唯一、可统计的拒绝原因。
8. 目标测试标签不能参与候选、配额、阈值或检查点选择。

## 14. 明确停止条件

- 选中增强出现任何控制占位符：停止。
- 计划三元组、目标情感或未编辑三元组保持率低于100%：停止。
- 配额不足：保存诊断后停止，不跨桶补齐。
- raw F1（原始F1）低于对应上一阶段：不继续提高预算或权重。
- 中性提升主要来自误检增长，或正/负F1任一下降超过0.5：拒绝。
- 多三元组召回下降：不进入模型结构增强阶段。

该顺序保证每轮只回答一个问题：过滤是否正确、生成器是否能完成编辑、250条分层数据是否优于150条、分层权重是否有独立收益。辅助头和轻量注意力适配器必须等数据增强闭环在至少两个代表方向有效后再单独制定实施计划。
