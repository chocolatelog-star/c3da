# C3DA 实验工作流

## 开始任何任务前

按顺序完整读取：

1. `实验记录与模型索引_CN.md`
2. `03_CD-C3DA下一阶段改进计划_CN.md`
3. 本 Skill（技能）

只有工作涉及外部 GPT（生成式预训练模型）交接时，再读取 `07`。详细改进设计统一维护在 `03`。

## 当前研究主线

- 终极目标：六个跨域 ASTE（方面级情感三元组抽取）方向分别超过 BGCA（双向生成跨域方法）。
- 保护 `rest16 -> laptop14` 的48.93，不在独立验收现场上做新实验。
- `laptop14 -> rest15` 当前研究基线为54.01，DANN（领域对抗网络）0.03、目标伪标签高层权重0.75。
- 五模块主线：目标真实句锚定、多三元组召回、局部契约与分层验证、缺口感知软配额与权重、方向自适应训练。
- 中性类别只作为辅助改善目标。暂停教师—学生、双生成器、损失强增权、强制固定总量、复杂配对/覆盖损失。

## 修改与确认

- 修改代码或实验语义前，先回顾流程并给用户一次简要说明：目标、改动文件/模块、参数变化、最早受影响阶段、复用边界和必要测试；用户确认后实施。
- 普通文档整理不反复确认；已经明确批准的整体方案可以连续实施。
- 不在 `master` 直接开发。候选通过完整 GPU（图形处理器）验收并获得用户许可后才能合并。
- 新功能和缺陷修复使用 TDD（测试驱动开发）：先写能正确失败的测试，再做最小实现。

## 智能体与成本

- 默认由主智能体串行完成。
- 只有至少两个真正独立的耗时任务，且并行预计同时降低总耗时和 Token（令牌）成本时，才使用子智能体；默认最多两个。
- 不为简单读文件、日志检查、实验监控、重复验证、小型审查或正式训练启动子智能体。
- 使用前简短说明原因；主智能体统一文档、代码、测试和结论。

## 阶段复用

每次给命令前说明：改动内容、最早失效阶段、真实下游、可复用阶段、必须重跑阶段、快速消融或完整验收。

运行只分三类：

1. 同一 `run_id`（运行标识）断点恢复。
2. 新 `run_id` 从一个完整父运行受控复用。
3. 从原始数据完整运行。

受控复用规则：

- 父运行必须同方向、同随机种子、同数据和模型，状态成功、工作区干净、`reuse_depth=0`、清单和哈希完整。
- 只能有一个父运行；子运行标记 `reuse_depth=1`，不得再作为父运行。
- 相关代码、配方字段、命令或输入哈希改变时，该阶段及真实下游全部失效。
- 产物只能通过专用入口按哈希导入本次运行目录；禁止手工复制、跨目录直接读取或混合多个历史运行。
- 新最佳、BGCA正式比较、六方向、多随机种子、合并 `master` 或累计完成大模块后，必须完整从头验收。

默认边界：只改评估则重跑评估；改最终训练则重跑最终训练与评估；改最终训练集则从组装训练集重跑；改增强则复用准备/抽取器/伪标签/生成器并重跑增强及下游；改伪标签则复用准备/抽取器；改抽取器或数据/方向/模型格式则重跑真实下游或全流程。

## 正式运行与显存

- 正式实验默认由用户在 CMD（命令提示符）运行；只有用户明确说“你来跑”时才代跑。
- 多步命令合并为一行 `cmd /c "..."`，并逐步解释用途。
- RTX 3070 8GB 默认训练批次1、评估批次2、梯度累积16、fp16（半精度）、gradient checkpointing（梯度检查点）、CUDA 0；实际以冻结配方为准。
- 所有训练、生成和筛选阶段显示进度条；同一运行标识支持恢复并验证 Git、配方、输入输出 SHA256。
- 模型默认从 `J:\nlp\models` 查找；下载时只保存 PyTorch 版本。

## 结果分析与文档

每次重要代码改进或实验结束后，整体更新：

- `实验记录与模型索引_CN.md`
- `03_CD-C3DA下一阶段改进计划_CN.md`

工作流或 GPT 交接内容变化时，按需整体更新 `02/07`；详细改进设计始终维护在 `03`。所有维护文档开头写北京时间更新时间，不在末尾无限追加重复叙述。

索引首屏必须显示六方向正式最佳、BGCA、差距和比较口径。历史只记录有研究或复现价值的大改动：日期、改动、Git 提交、运行身份、raw/fixed 指标、成功/失败和简短分析。小修复不改变实验语义时可合并记录。

分析必须报告 raw P/R/F1、fixed F1、正负中性、单/多三元组、FN/FP、增强选择与有效权重。raw F1 是主指标；不得用诊断最高值替代正式完整结果。

## 清理与失败

- 未经用户明确许可不得删除任何文件、模型、检查点或运行目录。
- 失败实验先保留指标、清单、命令、日志和首次错误，文档标记建议删除；用户批准后才清理。
- CUDA OOM（显存不足）、进程崩溃或连续失败时停止自动重启并报告阶段和日志，不通过删除产物掩盖问题。

## BGCA 原版复现边界

- BGCA 基线改造只允许增加旁路记录、逐行中间结果、环境/代码/数据哈希、阶段状态、断点恢复和8GB兼容运行器。
- 不改变源数据、标签格式、共享模型顺序、生成/过滤逻辑、损失、优化器语义、检查点选择或评估公式。
- 论文结果是5次运行均值；单随机种子只能做接近性检查。
- 原版使用 T5-base、学习率3e-4、物理批次16、梯度累积2，并按源域开发集选择训练轮数/检查点。3070适配必须用回归测试证明优化尺度等价。
- 不使用 `--clear_model` 自动删除检查点。
