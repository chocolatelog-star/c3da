# C3DA 实验工作流

## 开始任何任务前

新 Codex 模型或新对话首次接手时，严格按 `AGENTS.md` 规定的入口顺序完成事实源和 Git（版本管理）只读核验；实验索引、`03` 和 `07` 按当前任务需要读取。

1. `AGENTS.md`
2. `.ai/PROJECT_STATE.md`
3. `.ai/CURRENT_TASK.md`
4. `.ai/DECISION_LOG.md`
5. 本 Skill（技能）

实验记录与模型索引、`03`、`07`按任务需要读取；涉及服务器时必须读取`服务器迁移与实验运行交接_CN.md`。详细改进设计统一维护在`03`。

协作角色、升级和通信规则以`AGENTS.md`为准。不再维护`00`、`02`或账号交接重复文档。能从仓库读取的事实不得向ChatGPT（聊天模型）或用户重复询问；存在关键歧义、文档冲突或实验含义变化时必须向用户确认。

## 当前研究主线

- 项目最高优先级是在2026年9月16日前完成并提交ICASSP 2027常规4+1页英文论文。9月8日前冻结方法、9月12日前冻结数字、9月15日前完成提交演练；任何新变量必须先评估时间代价。
- 终极目标：六个跨域 ASTE（方面级情感三元组抽取）方向分别超过 BGCA（双向生成跨域方法）。
- 保护 `rest16 -> laptop14` 的48.93，不在独立验收现场上做新实验。
- `laptop14 -> rest15` 当前研究基线为54.01，DANN（领域对抗网络）0.03、目标伪标签高层权重0.75。
- 当前在`laptop14 -> rest15`的目标伪标签形成阶段研究Dependency/POS Graph（依存/词性图）与四头RGAT（关系图注意力网络）；最终ASTE模型尚未批准使用图结构。
- 完整Element Salience（元素显著性）＋Multi-Element Coverage（多元素覆盖）Treatment（实验组）相对普通RGAT改善multi recall（多三元组召回）和元素缺失，但未同时超过无图T5，因此只属于`QUICK_DIAGNOSTIC`（快速诊断），未进入Graph Freeze（图模块冻结）。
- 当前唯一任务是Focus-only（仅聚焦）与Coverage-only（仅覆盖）组件归因；固定DANN（领域对抗网络）为0、损失系数0.05、图结构、数据和训练设置，不进行系数、batch（批大小）、图层或注意力头网格。实时边界以`.ai/CURRENT_TASK.md`和`03`为准。
- 固定Generator Embedding FGSM Quick Ablation（生成器嵌入快速梯度符号法快速消融）已经完成并输出`NO_FGSM_GENERATOR_ROUTE`：raw/fixed F1为53.76/54.65，multi F1/召回及负面F1退化。永久关闭epsilon、损失比例、作用范围与结构定向搜索；实现、CUDA（统一计算设备架构）修复和零更新入口审计只作负结果基础设施保留。
- 中性类别只作为辅助改善目标。暂停教师—学生、双生成器、`k=2`、损失强增权、结构/质量权重、回放、NLL/EOS/ECAL训练、强制固定总量及未经上游供给证据批准的复杂配对/覆盖损失。

## 修改与确认

- 修改代码或实验语义前，先回顾流程并给用户一次简要说明：目标、改动文件/模块、参数变化、最早受影响阶段、复用边界和必要测试；用户确认后实施。
- 普通文档整理不反复确认；已经明确批准的整体方案可以连续实施。
- 新模型首次接手只做读取、Git（版本管理）身份核验和状态复述；未得到用户新的明确批准前，不修改训练代码、不启动GPU实验、不删除文件。交接批准不等于研究变量实施批准。
- 不在 `master` 直接开发。候选通过完整 GPU（图形处理器）验收并获得用户许可后才能合并。
- 修改前创建新分支；禁止跨运行复用或混合产物。每次正式运行必须保存完整训练命令和所有关键输入/输出 SHA256（哈希）。
- 新功能和缺陷修复使用 TDD（测试驱动开发）：先写能正确失败的测试，再做最小实现。
- 对同一冻结计划尝试新的生成提示或解码接口时，先锁定输入、模型、实现哈希、输出数、重试数和停止门槛；一次性接口失败后，不得通过换beam、长度、短语边界、顺序、约束范围或重试进行隐性参数搜索，除非新的独立证据和用户批准明确开启不同研究变量。

## 阶段复用

每次给命令前说明：改动内容、最早失效阶段、真实下游、可复用阶段、必须重跑阶段、快速消融或完整验收。

运行只分三类：

1. 同一 `run_id`（运行标识）断点恢复。
2. 新 `run_id` 从一个完整父运行受控复用。
3. 从原始数据完整运行。

受控复用规则：

- 父运行必须同方向、同随机种子、同数据和模型，状态成功、工作区干净、`reuse_depth=0`、清单和哈希完整。
- 只能有一个父运行；子运行标记 `reuse_depth=1`，不得再作为父运行。
- 相关代码、配方字段、命令或输入哈希改变时，该阶段及真实下游全部失效。
- 产物只能通过专用入口按哈希导入本次运行目录；禁止手工复制、跨目录直接读取或混合多个历史运行。
- 新最佳、BGCA正式比较、六方向、多随机种子、合并 `master` 或累计完成大模块后，必须完整从头验收。

默认边界：只改评估则重跑评估；改最终训练则重跑最终训练与评估；改最终训练集则从组装训练集重跑；改增强则复用准备/抽取器/伪标签/生成器并重跑增强及下游；改伪标签则复用准备/抽取器；改抽取器或数据/方向/模型格式则重跑真实下游或全流程。

## 正式运行与显存

- 正式实验默认由用户在 CMD（命令提示符）运行；只有用户明确说“你来跑”时才代跑。
- 用户没有明确说“你来跑”“帮我直接跑”或同等含义时，默认交付止于代码修改、必要测试和从 CMD（命令提示符）开始的完整单行实验命令；“确定”“按你说的做”“继续”只表示批准当前实现，不构成代跑实验授权。
- 当前实验默认在服务器执行，命令使用一行Bash（命令解释器）并把输出写入`/root/autodl-tmp/CD-C3DA-runs/`、临时文件写入`/root/autodl-tmp/tmp/`；除非用户明确要求本地命令，不再默认给Windows CMD（命令提示符）命令。
- 当前服务器为RTX 4090约24 GB显存；服务器环境、端口、提交和目录以`服务器迁移与实验运行交接_CN.md`为准。本地RTX 3070 8GB只用于用户明确要求的本地GPU任务，默认训练批次1、评估批次2、梯度累积16、fp16（半精度）和gradient checkpointing（梯度检查点）。实际实验参数始终以冻结配方为准，不能因服务器显存更大临时改变batch或优化语义。
- 4090默认并行2个独立实验；只有单任务峰值不超过约7 GB且三任务后仍预留至少3 GB时才允许3并行。并行任务必须具有独立运行目录、日志、检查点和恢复状态，不共享可写产物。
- 代码、审查或本地测试预计超过30分钟且服务器无可运行任务时，主动建议用户切换无GPU模式或关机，并说明下一次预计需要GPU的时间。
- GPU服务器只在本地CPU测试、必要工程复审、提交、推送、服务器提交核验和5至10步烟雾测试方案齐全后开启。目标是提交后可直接运行；禁止让服务器开机后再继续长时间现场改代码。
- 服务器长运行期间不切换提交或修改同一工作目录；本地并行推进论文、结果整理和下一任务CPU工作。
- 所有训练、生成和筛选阶段显示进度条；同一运行标识支持恢复并验证 Git、配方、输入输出 SHA256。
- 模型默认从 `J:\nlp\models` 查找；下载时只保存 PyTorch 版本。

## 结果分析与文档

预注册的黄金观察值（实际观测）必须与筛选配额（选择上限）分开记录；不得用筛选配额替代黄金观察值。正式比较只以当前最佳（已验证最佳）为准，不以诊断峰值替代。

实验完成不是“进程结束”或“指标落盘”，而是完成分析闭环。拿到结果后无需等用户追问，必须主动依次完成：

1. 本地核验实验身份、代码/配方、复用关系、数据边界、检查点选择和运行完整性。
2. 立即给出 Codex 初步实验分析：相对正式基线与 BGCA 的差距、P/R/F1 与分类/结构变化、FP/FN、机制是否生效、成功/失败及原因。不得只报指标或只说运行完成。
3. 将标准化证据同步给 ChatGPT 做独立研究分析，并等待完整回复；重要正式结果不得省略此步。
4. 核验 ChatGPT 建议是否符合本地代码、3070 8GB、数据隔离和复用边界，再主动向用户给出综合结论与唯一下一步建议。
5. 明确下一步的研究问题、唯一变量、最早受影响阶段、可复用/必须重跑阶段、通过/停止门槛；代码或实验仍须用户批准后执行。
6. 按下述范围整体更新项目文档。

每次实验或诊断的最终交付必须显式列出“实验结论”“唯一下一步建议”“ChatGPT 同步状态”；不得把其中任何一项留给用户追问。同步请求也必须要求 ChatGPT 返回结论和唯一下一步，而不只是解释指标。

无论实验成功、失败、门控未通过、程序报错或仅完成部分阶段，完成现有证据分析后都必须主动给出下一步建议；建议需说明是继续、修复、停止路线还是转入诊断，不得只报告结果等待用户追问。

所有已经完成模型训练的实验都必须运行最终目标测试并报告 raw/fixed F1、P/R、FP/FN、情感与单/多三元组细分。无金标机制门控继续在最终测试前运行并记录，但门控失败只表示“机制不晋级”，不得再阻断最终评价；此时结果明确标记为“门控失败、测试仅供报告”，不能用偶然的目标测试提升覆盖预注册失败，也不能用目标金标回改本轮阈值、配额或检查点。纯 `DIAGNOSTIC`（诊断）且没有训练模型的任务不要求目标测试。

若 ChatGPT 暂时不可用，先交付完整本地分析和暂定下一步，明确标记“外部分析待同步”；不得因此只报状态，也不得把暂定建议冒充 ChatGPT 结论。一次交付至少包含“有效性、结果对比、细分诊断、机制判断、下一步”五部分。

每次重要代码改进或实验结束后，整体更新：

- `实验记录与模型索引_CN.md`
- `03_CD-C3DA下一阶段改进计划_CN.md`

工作流或 GPT 交接内容变化时，按需整体更新 `02/07`；详细改进设计始终维护在 `03`。所有维护文档开头写北京时间更新时间，不在末尾无限追加重复叙述。

文档实行双目录同步：用户日常打开的`J:\nlp\CD-C3DA`是正式阅读入口，当前实际开发工作树是实验分支事实源。每次修改`AGENTS.md`、`.ai`三份控制文档、三份Chat Sol镜像、实验索引、`03`、`07`、服务器交接或项目Skill后，必须在同一回合把相同文本同步到正式入口与当前开发工作树；提交前逐文件做规范化文本一致性检查，并分别提交对应分支。不得只更新一边后把任务报告为文档已维护。若某一目录没有对应文件、存在未提交的用户改动或无法安全同步，必须明确报告，不得覆盖或猜测。

分析必须报告 raw P/R/F1、fixed F1、正负中性、单/多三元组、FN/FP、增强选择与有效权重。raw F1 是主指标；不得用诊断最高值替代正式完整结果。

## ChatGPT 与 Codex 同步

- ChatGPT（聊天模型）负责只读研究分析：判定 `DIAGNOSTIC`（诊断）、`QUICK_ABLATION`（快速消融）或 `FULL_RUN`（完整运行），检查数据泄漏与复用风险，提出2–3条路线及推荐方案。
- Codex（代码智能体）负责核对本地代码、配置、日志和运行清单；向用户说明一次方案并获得批准后，实施、做必要测试、给出完整单行命令并回填文档。用户是唯一审批者。
- Codex 发出同步请求后必须等待 ChatGPT 完整回复；未完成时明确报告“仍在等待”，不得把 Codex 自己的判断写成 ChatGPT 结论，也不得提前进入下一研究步骤。
- 实验结果到达后由 Codex 先完成本地证据核验和初步分析，再同步 ChatGPT；ChatGPT 返回后由 Codex 做可实施性复核并主动交付综合分析与下一步。禁止以“已完成”“指标如下”结束实验回合并等待用户再次询问分析。
- ChatGPT 回复完成后默认使用精简转述：只报告核心结论、推荐路线、Codex 本地核验后的同意/异议、具体改动和实验边界；不重复粘贴全文。只有用户要求详细解释时才展开。
- 明确区分三层状态：`ChatGPT 建议`、`Codex 已核验`、`用户已批准`。每个可独立验证的研究模块结束后同步一次；不等待多个研究变量混合跑完再分析。
- 日常同步默认只发送6行增量：`RUN/CODE/CHANGE/REUSE/RESULT/BOUNDARY`，完整清单只给证据路径。ChatGPT 日常回复压缩为判定、最多3条证据、风险、唯一下一变量、复用边界、通过/停止门槛。
- 只有新最佳、`FULL_RUN`、BGCA正式比较、新方向/多随机种子、复用身份异常、泄漏风险、混变量、复现异常或用户要求详细分析时，才展开完整13项报告。
- 文档按影响分级：普通诊断/快速消融只更新实验索引；研究路线变化再更新 `03`；新最佳、重大失败或跨方向结论再更新 `07`；实验纪律变化才更新 Skill。用户明确要求每次整体维护的文件仍优先遵守。
- 长期事实源是 GitHub（远程仓库）、实验索引、`03`、`07` 和本 Skill。GitHub 推送失败时，Codex 读取本地 Git（版本管理）提交、文档和运行产物，将必要字段直接发送给 ChatGPT；本地提交仍有效，但 ChatGPT 不能自行审计未推送代码。
- 每轮同步按实际可用性提供：代码身份与差异；实验身份、方向、随机种子、研究问题和唯一变量；父运行、`reuse_depth`、复用/重跑阶段；目标测试文本/金标访问和参数选择依据；完整指标；候选到训练的机制漏斗；命令、配置、指标、日志和异常路径。不可观测项标记为“当前不可观测”，不得猜测。
- ChatGPT 建议不是批准指令。Codex 必须核验建议与真实代码和数据边界一致，再交用户决定；未批准不得改代码或启动实验。

## 清理与失败

- 未经用户明确许可不得删除任何文件、模型、检查点或运行目录。
- 失败实验先保留指标、清单、命令、日志和首次错误，文档标记建议删除；用户批准后才清理。
- CUDA OOM（显存不足）、进程崩溃或连续失败时停止自动重启并报告阶段和日志，不通过删除产物掩盖问题。预注册机制门控失败不属于程序崩溃：保存门控失败状态后继续最终评价，再将实验判为不晋级。

## BGCA 原版复现边界

- BGCA 基线改造只允许增加旁路记录、逐行中间结果、环境/代码/数据哈希、阶段状态、断点恢复和8GB兼容运行器。
- 不改变源数据、标签格式、共享模型顺序、生成/过滤逻辑、损失、优化器语义、检查点选择或评估公式。
- 论文结果是5次运行均值；单随机种子只能做接近性检查。
- 原版使用 T5-base、学习率3e-4、物理批次16、梯度累积2，并按源域开发集选择训练轮数/检查点。3070适配必须用回归测试证明优化尺度等价。
- 不使用 `--clear_model` 自动删除检查点。
