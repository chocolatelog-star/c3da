## 今日遗留的六项实验

### 1. 本地 extractor 复现

等待当前本地训练完成，然后比较：历史 golden extractor、服务器 batch=1 extractor、本地 RTX3070 extractor。

必须记录：数据 hash、代码提交、Python/PyTorch/CUDA/transformers 版本、训练配置、模型 hash、source-dev Raw/Fixed F1、target pseudo 行数、high-precision pseudo 行数和 pseudo semantic hash。

这项不读取 target-test gold 进行参数选择；若发现代码、数据或处理逻辑不一致，先暂停参数调优。

### 2. upstream-only batch 实验

只允许运行：

```text
extractor -> source-dev evaluate -> target pseudo generation
```

禁止运行 generator、augmentation、complete_multi、final_train 和 target-test evaluation。

固定 T5、数据划分、tokenizer、解码、seed=1000、learning rate=3e-4、25 epochs、fp16、gradient checkpointing、DANN=0 和 pseudo filtering，只比较：

- `micro=1, accumulation=16, effective=16`
- `micro=8, accumulation=2, effective=16`
- `micro=16, accumulation=1, effective=16`
- `micro=16, accumulation=2, effective=32`（重点补做）
- `micro=32, accumulation=1, effective=32`

已有 batch=8/16/32 的 extractor 能复用就直接 evaluate/pseudo，不重复训练。每组记录 source-dev 指标、训练时间、峰值显存、optimizer steps、pseudo 数量、high-precision 数量、情感分布和语义 hash。最终 recipe 交给 Chat 决定。

### 3. 固定 extractor 的下游 batch 对比

固定同一个 extractor、pseudo、generator、augmentation 和 final train 数据集，只改变 final_train 的 batch/accumulation。该实验用于区分下游优化差异，不能使用各 batch 自己重新生成的上游产物。

这项必须在固定上游产物明确后启动。

### 4. Batch16 单步梯度与参数更新审计

使用同一初始模型、同一 16 条样本、同一随机状态，比较：

- `batch=1, accumulation=16`
- `batch=4, accumulation=4`
- `batch=8, accumulation=2`
- `batch=16, accumulation=1`

记录 loss、逐参数梯度、optimizer update、参数差异范数和尾 batch 行为。

### 5. 真实样本数归一化实验

比较当前 batch mean loss 与按真实有效样本数归一化的 loss，重点观察 batch=8/16/32 的梯度、更新幅度和训练稳定性。先做小规模可重复验证，再决定是否进入正式训练。

### 6. 带句法图的完整 Graph/Control A/B

复用已有 Phase A，不重新训练提取器。修复后的代码从现有 Control/Treatment 产物继续运行：

```text
pseudo filtering -> generator -> target-anchored augmentation -> validation -> final_train -> target evaluation
```

两组下游配置完全一致，唯一差异是 `graph_enabled=false` 与 `graph_enabled=true`。输出 Control、Graph、Graph-Control delta 以及 single/multi-triplet 指标。

## 2026-09-01 正式运行入口

以下入口均支持独立输出目录、断点续跑和中文/JSON 汇总。指定多个 GPU 时，上游和下游 batch 矩阵默认按 GPU 数并行。

### upstream-only batch 矩阵

只运行提取器、source-dev F1 和目标伪标签，不进入生成器和最终训练：

```bash
python run_upstream_batch_matrix.py --recipe configs/recipes/rest16_to_laptop14_best_v1.json --output_root runs/upstream_batch_matrix --project_root . --groups 1x16,8x2,16x1,16x2,32x1 --gpus 0,1,2,3 --resume
```

### 固定上游的下游 batch 矩阵

所有组固定同一 final train/dev、target test 和上游身份，只改变最终训练 batch：

```bash
python run_fixed_upstream_downstream_batch_matrix.py --shared_run runs/reproducible/rest16_to_laptop14_best_v1/公共上游运行目录 --output_root runs/fixed_upstream_downstream_batch_matrix --project_root . --groups 8x2,16x1,16x2,32x1 --gpus 0,1,2,3 --resume
```

### Batch16 梯度与真实样本归一化审计

该命令只执行单步更新，不读取 target-test：

```bash
python batch_gradient_parameter_audit.py --model_path models/t5-base-py --train_file runs/reproducible/rest16_to_laptop14_best_v1/公共上游运行目录/extract_train.jsonl --output runs/audits/batch16_gradient_parameter_audit.json --cuda 0 --seed 1000 --learning_rate 0.0003
```

### Graph OFF / Graph ON 完整 A/B

同一 Phase A 同时生成 Control 和 Graph，随后用相同下游参数分别运行完整流程并输出 F1 差值：

```bash
python run_graph_control_ab.py --phase_a_output runs/graph_control_ab/phase_a --full_output_root runs/graph_control_ab/full --recipe configs/recipes/laptop14_to_rest15_m1_syntactic_rgat_pseudo_quick_ablation_dann0_v1.json --graph_cache_dir graph_cache/graph_cache_resume --parser_dir models/stanza_resources --model_path models/t5-base-py --train_batch_size 16 --gradient_accumulation_steps 1 --cuda 0 --seed 1000 --resume
```

图实验使用独立的 `t5_absa_train_graph.py`。历史最佳仍使用 `t5_absa_train.py`，避免图训练审计逻辑改变 48.93% 历史最佳语义。
